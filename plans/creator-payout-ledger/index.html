Creator Payout Ledger

Move creator payout state to an append-only ledger. Earnings, holds, reversals, fees, tax withholdings, and settlements become immutable events; balances become replayed projections; payout scheduling reads from those projections.

Boundaries

flowchart TD
  Sales[Sales/refunds] --> Writer[Ledger writer]
  Writer --> Ledger[Append-only ledger]
  Ledger --> Projection[Balance projection]
  Projection --> Scheduler[Payout scheduler]
  Scheduler --> Processor[Processor adapter]
  Ledger --> Audit[Replay/audit]

Existing Rules Or ADRs

  • Supports ADR 0003 by making payout state replayable and auditable.
  • Risks ADR 0002 if the event store depends on database-specific stream behavior.
  • Tensions with the rule against new persistence models.

Rule Tension And Tightening

  • The cleanest design creates a new financial source of truth.
  • Loosening the persistence rule may improve auditability, but only with migration, replay, reconciliation, and rollback gates.
  • Add a financial-state rule requiring replay tooling, projection drift alerts, processor reconciliation, and rollback or compensation paths.

Alternatives Considered

  • Extend existing payout table: cheap, weaker replay.
  • Append-only audit table beside current state: safer, drift risk.
  • Managed ledger product: strong controls, vendor lock-in.
  • Relational append-only ledger: powerful alternative, likely simpler.
